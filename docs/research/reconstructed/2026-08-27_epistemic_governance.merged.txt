P  Statistical Governance and Strategy Search Validation
P  Multiple Testing and Overfitting Mitigation Protocols
P  Evaluating parameter spaces across {M ~ 10^3} deterministic trading strategies over {T ~ 10^2-10^3} observation windows inevitably triggers the data-snooping problem1. When numerous candidate rules are evaluated against historical return series, standard unadjusted test statistics fail because the optimization process selects strategies that have capitalized on sample-specific noise1. Naïve per-comparison standard errors treat the selected winner in isolation, disregarding the cumulative probability of false discovery inherent in evaluating an entire model family1.
P  To control the familywise error rate and the false discovery rate across extensive strategy searches, five distinct statistical frameworks offer varying degrees of power, computational tractability, and distributional flexibility1.
== TABLE START ==
R | Statistical Framework | Null Hypothesis (H0​) | Core Resampling or Adjustment Mechanism | Asymptotic & Sample Requirements | Suitability for M≈103,T≈102–103
R | White's Reality Check (White, 2000) | {max_k E[f_k] <=} (No strategy outperforms the benchmark) | Stationary bootstrap of performance loss differentials centered around zero1. | Requires strictly stationary, {alpha}-mixing series; {T >= 500}4. | Low to Moderate. Highly conservative; loses power when flooded with poor strategies4.
R | Hansen's SPA Test (Hansen, 2005) | {max_k E[f_k] <=} (No strategy outperforms the benchmark) | Studentized, recentered stationary bootstrap trimming irrelevant, poor candidates2. | Requires stationary, weakly dependent series; {T >= 250}4. | High. Excellent omnibus validation; avoids conservative bias of White's test2.
R | Deflated Sharpe Ratio (Bailey & López de Prado, 2014) | {True SR <=} ({SR*} is expected max Sharpe under noise) | Closed-form adjustment accounting for non-normality, trial count, and trial variance1. | Parametric moment stability; {T >= 100} per candidate track record7. | Optimal for initial fast-filtering of single top-performing candidates1.

P  White's Reality Check creates a composite null distribution by recentering all strategy performance differentials to zero1. While structurally sound, the test becomes overly conservative when the search pool includes a large proportion of underperforming models, as the variance of the supremum statistic is inflated by irrelevant alternatives4. Hansen's Superior Predictive Ability (SPA) test resolves this limitation by standardizing the test statistic and implementing a data-dependent threshold that centers only strategies with non-negative sample performance, effectively discarding uninformative noise2. Hansen's SPA requires stationary, weakly dependent time series and achieves stable bootstrap asymptotics when {T >= 250}4.
P  The Deflated Sharpe Ratio (DSR) provides an analytically tractable, computationally efficient adjustment for performance inflation stemming from selection bias, sample length, and non-Gaussian return distributions1. DSR evaluates whether an observed Sharpe ratio {SR_hat} exceeds the expected maximum Sharpe ratio {E[max_n SR_n]} generated by {N} independent and identically distributed trials under the null hypothesis of zero true skill7. The expected maximum Sharpe ratio is estimated analytically via extreme value theory:
P  {E[max_{n<=N} SR_n] ~ sqrt(V[SR_n]) ((1-gamma)Phi^-1(1-1/N) + gamma*Phi^-1(1-1/(Ne)))}
P  where {V[{SR_n}]} represents the empirical variance across the evaluated strategy Sharpe ratios, {gamma ~ 0.57721566} is the Euler-Mascheroni constant, {Phi} is the standard normal cumulative distribution function, and {e} is Euler's base7. The DSR is computed as the Probabilistic Sharpe Ratio (PSR) of the observed maximum Sharpe ratio {SR_hat} relative to the hurdle benchmark {SR* = E[max_n SR_n]}7:
P  {DSR = Phi( (SR_hat - SR*) sqrt(T-1) / sqrt(1 - gamma_hat_3 SR_hat + ((gamma_hat_4-1)/4) SR_hat^2) )}
P  where {gamma_hat_3} and {gamma_hat_4} denote the sample skewness and kurtosis of the selected strategy's returns, and {T} is the number of return periods7. DSR operates reliably with {T >= 100} observations, provided the estimated higher moments are well-conditioned7.
P  The Probability of Backtest Overfitting (PBO), implemented via Combinatorially Symmetric Cross-Validation (CSCV), segments a time series of {T} observations into an even number of contiguous slices {S} (such as {S = 16}, which generates {C(16,8) = 12,870} combinatorial training and testing splits)5. For each combination, strategies are ranked in-sample on the training partition ({S/2} slices) and subsequently evaluated on the out-of-sample testing partition5. PBO computes the proportion of combinatorial splits where the top in-sample strategy delivers below-median out-of-sample performance5. For {M = 1,054} strategies across {T ~ 10^2-10^3} windows, CSCV requires {T >= 500} to ensure each slice contains adequate return realizations without violating time-series structure5.
P  For automated strategy generation pipelines, the optimal statistical protocol combines DSR as an instant screening filter during search, followed by Romano-Wolf stepdown adjustments or CSCV/PBO computation on the candidate survivor set before declaring an edge1.
P  Pre-Run Power Analysis and Execution Gating
P  A common failure mode in empirical backtesting is executing trials in regimes where statistical power is virtually non-existent9. In the presence of high underlying variance, small sample sizes guarantee that estimated effect sizes will either fail to achieve significance or, conditional on passing an unadjusted significance threshold, represent severe magnitude overestimations (Type M errors) or sign errors (Type S errors).
P  Given a measured per-cycle standard deviation of {sigma_unpaired = 6.6 bps} and a paired difference standard deviation of {sigma_paired = sigma_d = 2.6 bps}, the required sample size {N} to detect a true underlying effect size {delta} at significance level {alpha = 0.05} ({z_{1-a/2} = 1.96}) and statistical power {1-beta = 0.80, 0.90, 0.95} is governed by standard power formulations12:
P  {N_paired = (z_{1-a/2}+z_{1-b})^2 sigma_d^2 / delta^2}
P  {N_unpaired,per_group = 2(z_{1-a/2}+z_{1-b})^2 sigma^2 / delta^2  ==>  N_total = 2 * N_unpaired,per_group}

P  The mathematical reality explains why {N = 534} cycles yielded an inconclusive {t = 0.37}12. When searching for a sub-1 bps effect (e.g., {delta = 0.25 bps}), an unpaired trial with {N = 534} cycles achieves only {9.00%} statistical power, meaning the experiment has a {91%} probability of generating a false negative12. Even under a paired experimental design, {N = 534} achieves only {60.33%} power for {delta = 0.25 bps} and {14.20%} power for {delta = 0.10 bps}12.
P  To prevent compute waste on underpowered trials, execution harnesses must enforce a deterministic pre-run gating check. Before allocating resources or initiating measurement cycles, the harness evaluates:
P  {N_required = ceil((z_{1-a/2}+z_{1-b})^2 sigma_hat_prior^2 / delta_threshold^2)}
P  If {N_available < N_required}, the harness rejects execution and calculates the minimum detectable effect (MDE) achievable under the available sample size constraints:
P  {MDE = (z_{1-a/2}+z_{1-b}) * sigma_hat_prior / sqrt(N_available)}

P  Machine-Executable Pre-Registration Frameworks
P  Autonomous systems that generate both execution logic and analytical prose are susceptible to automated hindsight bias: constructing post-hoc explanations for anomalies encountered during execution1. Findings from open-science reforms demonstrate that pre-registering hypotheses and analysis plans before observing data eliminates selective outcome reporting and {p}-hacking.
P  For autonomous agent architectures, pre-registration must be enforced cryptographically within the test orchestration pipeline:
P  The agent generates a structured pre_registration_manifest.json before accessing target market data or executing live cycles. This manifest defines the formal hypothesis, expected effect size ({delta}), target statistical power ({1-beta >= 0.80}), primary evaluation metric (such as Deflated Sharpe Ratio), exact data split partitions, purging boundaries, and null control specifications2. The harness computes the SHA-256 digest of the manifest and records it into an append-only Git commit tree. The execution engine injects data streams only after verifying the cryptographic commitment, and the compilation step rejects any report referencing metrics or data boundaries that deviate from the pre-registered manifest2.

== TABLE START ==
R | Oversight Pattern | Mechanism of Action | Systemic Failure Mode | Marginal ROI per Human Minute

R | Imperative Tasking ("Do X, then Y") | Directs implementation along narrow execution sub-paths15. | Biases the search space; introduces human latency into execution loops15. | Low. Agent executes rapidly but potentially on flawed sub-tasks15.

== TABLE END ==
P  Large language model agents possess high local task execution bandwidth and synthesize boilerplate logic rapidly, but they suffer from localized context entrapment—optimizing within the bounds of a prompt-specified premise without verifying whether the premise itself is valid15.
P  When a human provides imperative task instructions, the agent executes the request without evaluating upstream soundness. Conversely, Socratic interrogation forces global belief-state entropy reduction: it redirects the agent's internal evaluation routines toward unexamined premises, triggering automated sweeping, control testing, and structural refactoring15. Human attention achieves maximum leverage when operating as an adversarial invariant prober rather than an operational dispatcher3.

P  Tamper-Evident Provenance and Retraction Economics
P  A critical vulnerability in autonomous repositories is the silent erasure of negative results. To ensure scientific integrity when human oversight is asynchronous or absent, the repository must make retraction computationally cheap and deletion structurally impossible:
P  Benchmark results are written to an append-only, content-addressed Merkle tree where each run is indexed by its monotonic sequence ID and input data hash. Claims in markdown documentation reference unique benchmark execution hashes; if a benchmark record is modified or pruned, the integrity check fails across the repository. Furthermore, retractions are formalized as first-class status transitions (CONFIRMED {->} REFUTED {->} SUPERSEDED) within the project metadata. An automated agent receives an optimization reward signal for successfully falsifying a prior claim via verified control runs, aligning the agent's objective with epistemic accuracy rather than monotonic claim accumulation1.
